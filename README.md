# Multimodal Chest X-Ray Report Generation Engine
## Phase 1: Data Pipeline & Architectural Strategy

This repository contains the foundational data engineering pipeline and architectural design for an automated vision-to-language medical report generation system. The objective is to take chest X-ray scans as inputs and generate coherent, clinically accurate diagnostic text.

---

## 1. Dataset Audit & Structural Analysis
A preliminary audit of the provided `KMC_original_csv.csv` dataset revealed a critical architectural challenge: **Data Leakage via Augmented UUIDs.**

* **The Problem:** The dataset contains multiple augmented or modified variations of identical base patient X-rays, tracking back to the same parent scan but labeled with distinct long UUID strings in the `IMAGE_NAMES` column. 
* **The Risk:** A standard random split would scatter these identical underlying images across both the training and validation sets. The model would effectively "memorize" the visual patterns of specific images rather than learning to generalize features, leading to artificially inflated accuracy metrics.
* **The Solution:** Implemented a grouping mechanism via `data_preprocessing.py` that maps the unique `IMAGE_LABELS` (base scans) to encapsulate all derivative UUID strings. Splitting is strictly executed across *groups*, ensuring complete isolation between training and validation data.

### Dataset Profile (Post-Deduplication)
* **Total Records Processed:** 1,498
* **Unique Patient Base Scans:** 502
* **Training Set:** 1,214 images
* **Validation Set:** 284 images
* **Data Split Ratio:** ~80% Training / ~20% Validation (Strictly Group-Isolated)

## 2. Proposed Baseline Architecture
To bridge the gap between computer vision and natural language processing, the system will utilize a classic **Encoder-Decoder** paradigm.

### Visual Encoder: DenseNet-121
* **Role:** Extracts dense visual features from the chest X-rays.
* **Justification:** DenseNet-121 is highly effective for medical imaging tasks because its dense connectivity pattern maximizes feature propagation across layers, making it exceptionally skilled at recognizing subtle geometric anomalies (such as infiltrates or cardiomegaly) without requiring massive parameter overhead.
* **Preprocessing:** Input images will be normalized and uniformly resized to 224x224 pixels to standardize spatial dimensions.

### Textual Decoder: Transformer Decoder
* **Role:** Consumes the visual feature vectors generated by the encoder to output diagnostic sentences token by token.
* **Justification:** Unlike older sequential models (like LSTMs), a Transformer decoder uses self-attention mechanisms to handle long-range dependencies within text, ensuring the generated reports maintain clinical coherence across multi-sentence paragraphs.
* **Preprocessing:** Text targets will be cleaned of extraneous whitespace, lowercased, and padded using structural start and stop tokens (`[START]` / `[STOP]`) to govern text generation boundaries.
